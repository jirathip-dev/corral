## Problem recap (source-grounded, #450 body)

Daemon restarts reset the Store rev to zero; `resume_from` full-snapshots only when the client cursor is AHEAD, and `FleetStore.accepts` rejects snapshots BELOW its retained rev, so a populated board can stay stale across a daemon restart while HTTP 200 marks it connected. Revision-only cursors cannot distinguish a different daemon lifetime that happens to reach the same or a higher revision.

## Protocol choice (smallest compatible)

Opaque per-daemon-lifetime **epoch**: 128-bit OS-RNG hex string minted per `Store` (shared by all clones of one daemon, unique per lifetime).

- `Snapshot`/`Delta` JSON gain an additive top-level `"epoch"` (serde-ignored by old clients; `#[serde(default)]`-style absence decodes to nil on iOS).
- `GET /events` reads an optional `Corral-Epoch` request header (sent alongside the numeric `Last-Event-ID`). When the epoch is ABSENT (legacy client), resume is exactly the old revision-only behavior. When it names ANY other lifetime (stale, or the literal `unknown` used by upgraded clients carrying a pre-#450 cursor), the daemon always answers with a full epoch-bearing snapshot of the CURRENT lifetime — even when the numeric rev is equal or lower.
- `resume_from_epoch` in the store owns the comparison; the plain `resume_from(Option<u64>)` API keeps its exact old contract (store-level tests unchanged).
- iOS scopes its numeric cursor to the epoch: `SSECursor {rev, epoch}`, persisted together (`fleetnotifier.lastEventId` + new `fleetnotifier.lastEventEpoch` legacy keys; per-host `cursorRev` + new `cursorEpoch` mirrors in `HostProfile`/`HostProfileStore` keys `fleetnotifier.hostProfile.cursorEpoch.<id>`).
- Client `accepts()`: cross-epoch SNAPSHOT = authoritative replacement when it rode the STREAM (`apply`/`ingest`); cross-epoch snapshot via PULL REFRESH (`applyRefresh`) is REJECTED (a racing stale HTTP response cannot overwrite the replacement stream state — same-lifetime monotonicity is preserved while the stream is the authority); cross-epoch DELTA = always rejected (only a full stream snapshot is an epoch boundary); same-epoch keeps the old `>=`/`>` monotonic rules; epoch-less frames (legacy daemon) keep exact legacy behavior.
- Old-generation stream callbacks stay blocked by the existing `connectionGeneration` gate (proven by a new test that would regress if the guard were removed).

## Discoveries / notes

- **HTTP client trap**: python `http.client` hangs reading chunked SSE keep-alive streams (frame arrives, but chunked read blocks); `curl -N -m N` reads the first frame deterministically. The Rust integration tests (axum oneshot) are unaffected.
- **Cargo freshness trap**: `cargo build` after an edit did NOT relink target/debug/corrald (fingerprint/mtime granularity); symptom: live daemon ran stale code while in-process tests were green. Remedy: `touch` the edited sources and rebuild. Worth remembering for any lane whose evidence runs the daemon BINARY.
- **Parallel XCTest session race**: a test that connects a stream twice on one ephemeral URLSession could crash with `Task created in a session that has been invalidated (NSGenericException)` under parallel execution when the first stream task was cancelled but not awaited before `invalidateAndCancel`. Fixed by awaiting the disconnect task (`if let t = disconnect() { await t.value }`) before reconnecting — test-only change.
- Full live-app end-to-end (app paired to daemon A, daemon killed, board converging) was NOT driven: simulator cannot reach the host loopback for a real daemon and the daemon's writer plane requires the host's real herdr + signed pairing; instead the evidence is (a) REAL daemon binary restart over the live herdr read socket with curl-verified epoch frames, and (b) REAL client convergence semantics in the simulator suite over real SSE bytes. Physical-iPhone run of the actual symptom remains the explicit human gate.
