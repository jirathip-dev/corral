## Diagnosis (from the render, base vs head, same device)

Frames from both heads (`*/night-large-default.png`, 1170x2532 @3x):

1. **The commit line's own pixels are byte-identical between base and head**
   — the commit row band (y 1650..1800) has **0** differing pixels on the
   AX3 frame; the OCR still flips. So nothing about the commit identity's
   rendering (plain monospaced `caption2` sha + `caption` subject) changed.
2. **The caption row grew 3 pt and pushed everything below it down 9 px.**
   The `RepoLabelChip` capsule is 19.0 pt tall (measured: 57 px @3x); the
   pre-#569 caption row was 16 pt — it is sized by the caption-semibold state
   label, not by the repo text — so the chip made the row 19 pt. Ink runs on
   `night-large-default`, base vs delivery: caption `435→440`, identity
   `502→511`, commit `581→590`, sheet divider `815→824` (+9 px each): the
   whole #558 worktree block, the divider and the loaded content moved down.
3. **Controlled position splices** (same frame, one variable): head frame
   shifted **up 9 px** → `abcdef1`; base frame shifted **down 9 px** →
   `abodef1`. The read flips with position alone on this device.
4. On the AX3 frames the position is *not* the trigger: pasting the caption
   band between base and fixed frames flips the read both ways, and narrowing
   the paste to the chip's capsule window alone (x 215..770) reproduces the
   flip — Vision's grouping of the header block is perturbed by the capsule's
   pixels there (the sha's pixels are identical). This is why the fix must
   keep the caption row's own geometry AND the Board's capsule footprint.

## The fix (`99234658`)

`RepoLabelChip` gains a `compact` variant: the capsule is **drawn exactly as
the Board draws it** (2 pt vertical padding — dot, hue ink, fill, border all
unchanged; measured 19.0 pt in the fixed frame, same as the round-1 head's)
while its **layout box** shrinks by that padding (a negative outer padding
affects layout only, never the drawing). The sheet passes `compact: true`;
every board call site keeps the default `false` and renders unchanged.

Result, measured on the same 17 Pro sim: the worktree block's rows sit at the
**base** y again (435 / 502 / 581 / 642 / 706 / 773 px @3x — identical to
base) with the capsule still 19.0 pt, and the protected check passes.
