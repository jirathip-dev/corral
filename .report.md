## Issue mapping

### #319 — status semantics

- `clients/egui/src/model.rs` and `ios/FleetNotifier/UI/BoardModel.swift` add parallel, pure presentation classifiers.
- Supervising requires canonical `done`, an identity-derived orchestrator role, and structured poll/watcher evidence from the existing adapter-projected reason/state-label field. Role alone and arbitrary prose do not qualify.
- Activity projections expose only generic Polling/Watcher labels and bounded counters. Raw command text is not returned to a view.
- Native iOS rows show the canonical `Finished` state plus a subordinate Polling line and an accessible `DisclosureGroup` evidence target. egui rows show the same state/activity split and the detail status panel exposes State, Activity, Evidence, and redacted command fields.

### #320 — grouped board presentation

- Both native clients use `Needs you → Working → Supervising → Finished → Idle`, omitting empty groups.
- Section headers include derived counts. Active supervising rows remain selectable even though their wire state is `done`.
- `contracts/state-tokens.json`, egui theme labels, and iOS state display labels use `Finished`; mark/rank/color/icon remain unchanged.
- Debug-only synthetic fixtures cover the grouped rows without changing live daemon, grants, drive, or lifecycle behavior.
