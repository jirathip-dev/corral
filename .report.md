## Problem (as filed)

After the #354 L3 egui cut, the retained read-only board rendered the idle
state-chip mark U+25E6 (white bullet) as the epaint replacement glyph U+25A1
(tofu square; pixel-verified in the L3 review evidence and re-verified on the
base PNG in this lane). `configure_fonts` survives in app.rs but only set
spacing; the cut removed the pre-cut glyph machinery with no replacement.

## Root cause (verified, not assumed)

epaint 0.36.1 default font chains (verified with fontTools cmap scans over
`epaint_default_fonts-0.36.1/fonts/*.ttf`):

- Proportional = Ubuntu-Light -> NotoEmoji-Regular -> emoji-icon-font
- Monospace = Hack -> Ubuntu-Light -> NotoEmoji-Regular -> emoji-icon-font
- U+25E6 (idle) is in NO default font -> epaint falls back to its
  replacement char U+25A1 (the tofu square). U+25CB (working) resolves via
  emoji-icon-font; U+2713 (done) is in no default font either, but herdr
  0.8.2 never emits `done` on the wire (finished panes fall back to idle),
  so no board chip can carry it.

## Fix (smallest correct option — the brief's option 1)

One shared helper + both install sites, NO bundled assets:

- `theme.rs`: new `pub(crate) board_font_definitions()` = egui
  `FontDefinitions::default()` with the toolkit's built-in Hack appended to
  the Proportional family (Hack ships inside epaint itself, so the retired
  #347 font-bundle machinery — repo assets + transcript_font_definitions —
  is NOT re-added).
- `app.rs configure_fonts` (desktop) and `web.rs WebCorralApp::new` (wasm)
  both install it. The wasm surface never called configure_fonts before
  (it keeps its own inline style block), which is why the tofu was visible
  in the demo evidence; the wasm board shares board.rs rendering, so both
  surfaces need the chain.

`contracts/state-tokens.json` untouched: the idle mark TOKEN stays "dot" —
only the display glyph resolution changed.
