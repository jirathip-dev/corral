## Provider revision contract (defined, per AC1)

`agent.read` responses carry `read.revision`: a monotonic
per-agent/output-source revision of the `recent_unwrapped` window — NOT the
fleet snapshot revision (the drive envelope's `rev`). Semantics:
`revision` 0/absent = legacy provider (bounded full-page fallback, no
provider revision); request `rev` == provider `revision` = UNCHANGED (provider
returns empty `text`; adapter returns an explicit empty result with the same
revision — no page re-transferred); any other case (first read, changed
output, wrap/restart where the provider counter reset below the cache) =
bounded window + the provider's current revision. Wire: request
`{"kind":"read_tail","lines","since_rev"}`; response result
`{"lines","blocks","source_rev"}`. Documented in `docs/OPERATIONS.md`,
`docs/corral/P4-conformance.md`, and the herdr.rs module docs.

## Honest upstream blocker

The live Herdr 0.8.2 provider does NOT support revisions. Re-verified
read-only at this base against the live socket
(`~/.config/herdr/herdr.sock`, `agent.read`, target `orch-hermes-brain`,
`source: recent_unwrapped`): no `rev`, `rev = 1`, and `rev = 999999` all
return `read.revision: 0` with byte-identical 929-byte bodies — see
`docs/design/evidence/issue-324/live-herdr-0.8.2-probe.md` (read-only JSON-RPC;
herdr rejects integer request ids, so string ids were used). This matches the
issue's own #314 verification. No live-provider incremental behavior is
claimed: against Herdr 0.8.2 the adapter keeps the bounded full-page fallback
and `source_rev` echoes the client's cached revision (pre-existing behavior).

## Measured probe (simulated provider, REAL adapter path)

`docs/design/evidence/issue-324/probe.sh` runs the committed probe test
(`adapters::herdr::tests::probe_read_tail_bytes_first_unchanged_changed`):
the real `HerdrAdapter::read_tail_since_with_rev` performs first/unchanged/
changed reads against a mock socket whose fixture provider implements the
contract (200-line ≈ 18 KiB long-running-pane window). Raw wire bytes
(incl. newline) from `probe.log`:

- first (no cached rev): request 105 B, response 20260 B, 200 lines, rev 59
- unchanged (cached rev 59): request 114 B, response 62 B, 0 lines, rev 59
- changed (cached rev 59): request 114 B, response 20260 B, 200 lines, rev 60

The unchanged read transfers 62 bytes instead of the full page (~99.7%
saving) and returns the explicit empty result; the changed read returns the
window with strictly newer revision 60.
