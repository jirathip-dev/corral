## Delivered client behavior

- Separate `fleetnotifier.backgroundRefreshEnabled` preference, OFF when
  absent. Pairing does not enable it. Its Settings binding does not request
  notification permission, register APNs, or mutate the visible-alert setting.
  Opt-out cancels owned hint requests immediately. UI discloses that the
  compatible authenticated relay is not yet available, private-path fetching,
  best-effort OS delivery, Low Power Mode/force-quit/path constraints, limits,
  metadata and retention. No notification-service extension was added.
- Closed v1 hint: exactly `v`, `type`, `host_id`, `aps`; `v` is numeric 1,
  `type` is `board_changed`, `host_id` is canonical base64 of a pinned 32-byte
  X25519 key, and `aps` has only numeric `content-available: 1`. Booleans,
  strings in numeric fields and additional keys are rejected. No URL,
  enrollment, prompt, output, repository/branch, agent or alert content is
  accepted. APNs push-type/background and priority 5 are sender HTTP headers;
  they cannot be inspected through `userInfo` and remain #544 obligations.
- Resolve only a matching local profile with a usable registration, signer,
  unexpired grant and permissible trust posture. Never derive a URL or an
  enrollment from the hint. Unknown/removed/unregistered/locally trust-denied
  profiles cause no network requests. A newly discovered remote pin mismatch
  permits only the necessary `/host-key` check and no `/snapshot` request.
- One fresh host-key GET, then at most one snapshot GET through the EXISTING
  CorraldClient session. No `/events`, transcript read, enrollment, internal
  retry or reconnect ladder. At most one in-flight hint per profile.
- At most one admitted attempt per pinned host per 30 minutes, two per device
  per rolling hour. Admission is persisted before networking, so errors and
  cancellation consume the attempt. Invalid/opted-out/refused deliveries do
  not create attempt records. Off/on and a fresh model do not reset quotas;
  clock rollback conservatively retains future-dated entries.
- A separate local task enforces the whole 15-second monotonic handler budget;
  it does not await an unresponsive remote operation. Every apply rechecks the
  elapsed budget. A single completion owner cancels network/deadline tasks,
  releases the in-flight claim and delivers completion only once. Refusal,
  cancellation and supersession return `.noData`; network error/expiry return
  `.failed`; an accepted and persisted snapshot returns `.newData`.
- Foreground cancellation uses a separate
  `UIScene.willEnterForegroundNotification` subscription. Existing
  `handleScenePhaseChange(_:)` is byte-identical (1,175 characters compared),
  respecting #545 ownership. Local removal eagerly cancels that host's work;
  re-resolution after awaits also catches direct profile-store removal.
  Lifecycle context, target-store identity, stream generation, revision,
  epoch and agents must still match the admitted read. New data wins even if
  the arriving hint claims a higher revision. An established epoch cannot be
  replaced or downgraded to an epoch-less snapshot. The handler never calls
  stream-only epoch-reset ingress or starts a stream.

## Persistence and restart boundary

New operational persistence is exactly:

- `fleetnotifier.backgroundRefreshEnabled`: Boolean preference, retained until
  changed under ordinary UserDefaults lifecycle.
- `fleetnotifier.backgroundHintAttempts.v1`: encoded array of at most two
  `{hostID, attemptedAt}` records. One-hour logical retention; lazy disk pruning
  on model launch or successful admission. Expired bytes may remain while the
  app does not run. Opt-out does not wipe quota and reopen its window.

No new snapshot/full-agent/transcript store exists. Accepted data reuses
BoardCacheStore's allowlist: composite identity, profile UUID, agent ID, state,
board timestamps/state-entered-at, display name/title/reason/tool, pane ref,
repo/branch/worktree basename and last-seen timestamp. Existing retention is
until replacement or host removal. Revision and epoch use HostProfileStore;
the active store also updates its existing legacy cursor mirror.

Preference, attempt metadata, board metadata and cursor survive ordinary
process termination through the existing best-effort persistence/file
protection. Full agents, tails, stream owners, verification state and in-flight
requests remain in memory only. A cold launch still needs a foreground stream
snapshot for a full delta base; a receipt before restored-model installation
fails closed. Tests re-open real cache files/defaults and construct a fresh
model, not a physically terminated/relaunched app. Actual OS restoration and
background file availability remain in the physical protocol.

Relay-side sender/device authentication, device isolation, revocation, remote
opt-out, opaque routing, independent APNs enrollment/consent and attempted-SEND
ceilings are NOT proven here. Client quotas cover only admitted callbacks the
process observes; they cannot count Apple-delayed/dropped attempts. #544 must
provide these controls and the exact request contract in
`docs/evidence/issue-546/device-protocol.md`. That document also defines the
unfilled offline, path-unavailable, disabled-refresh, Low Power Mode,
force-quit, race, visible-alert independence and freshness measurements.
