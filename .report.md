Acceptance map

1. Host updates

scripts/update-corral.sh now treats the developer checkout as read-only input.
It fetches origin/main, archives that revision into a disposable source tree,
and builds there with CORRAL_BUILD_ID set to the fetched revision. It does not
inspect or require a clean tree, a main branch, or a clean index, and does not
pull, checkout, reset, clean, or merge the developer checkout. The completed
artifact is copied only after the build succeeds and the launchd execution
path is resolved. Binary drift is still checked when the commit does not move.

2. Preservation and rollback

scripts/install-corral.sh keeps the existing release-directory swap and adds
transaction snapshots for the existing app bundle, Corral config directory,
and daemon/update/rotation launchd plists. If setup or its health path fails,
launchd jobs are stopped best-effort, those external paths are restored, the
previous release is restored, and the prior jobs are bootstrapped best-effort.
Device-key and grant files remain inside the preserved config directory.

3. Build identity and client warnings

The daemon exposes GET /version and projects the same non-secret
BuildIdentity into every snapshot. The identity carries build_id, package
version, protocol_version, and schema_version. CI supplies the release commit
as CORRAL_BUILD_ID; local builds use a development marker.

The typed Rust client, egui desktop/web client, and iOS client decode the
additive field. The egui Settings health row and iOS Settings section show
compatible host version information, or an actionable warning for an absent,
old-schema, or incompatible-protocol identity. An old host is therefore
unknown rather than silently treated as compatible.

4. Dirty feature checkout regression

scripts/test-host-update-compat.sh creates a local bare origin, clones a dirty
feature checkout, advances only origin/main, and uses a cargo/launchd fixture.
It proves the installed artifact comes from origin/main, the cargo working
directory is isolated, the feature branch and tracked diff are unchanged, the
untracked developer file survives, and the daemon restarts once. A
non-source/release-shaped updater returns nonzero and logs release-required;
it no longer reports a successful silent skip.

5. Recovered-key grant boundary

clients/egui/tests/identity_recovery.rs now reads the grant set back after the
recovered key is registered and the remote grant mutation is sent. The test
asserts the persisted recovered key and read_tail grant, then drives the signed
read path again. Test diagnostics contain no key IDs or temporary paths.

6. Promotion gate

ios/host-compatibility.json is an explicit compatibility declaration.
scripts/check-host-compatibility.py rejects wrong protocol/schema values,
missing artifact evidence and declarations, and unverified string-only
artifact names. Release packaging embeds the declaration and the release and
TestFlight workflows run the validator before packaging or promotion.
The canonical P4 contract and docs describe /version and build_identity.
