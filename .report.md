## Acceptance mapping

A. TOUCH FEEDBACK + HAPTICS — `BoardPressStyle` (dim + slight scale while
`isPressed`, released on up/cancel) on agent rows, repo chips, and the banner
close; system controls (Done/Retry) already show native press feedback. One-shot
selection haptic on agent-row tap and Done close via an injectable model seam;
deep links and auto-demo opens are silent; drag paths never tick. Chip hit
targets >= 44 pt (`frame(minHeight: 44)`); row VoiceOver labels/hints/summaries
unchanged (source-wiring pinned).

B. REPO FILTER CHIPS — horizontal row under the pinned chrome: `All N` + one chip
per workspace repo with live count (orphan agents surface under All only).
Selection filters WHICH agents the #362 status sections bucket — sections keep
their locked order over the filtered set. `BoardModel.repoFilters/agents/reconcile`
are pure and unit-tested. The choice is model-owned so it persists across
pull-to-refresh and tab/foreground refresh; a repo that vanishes from the fleet
reconciles to All. No search box.

C. RELIABLE RECENTS-SHEET REOPEN — root cause: the presentation target was a
STICKY model latch (`recentsAgentId`, never cleared on dismissal) behind an
equality-guarded onChange, while SwiftUI auto-nils only the view's item binding
at dismissal. A repeat request (same agent after dismissal) compared equal, and
taps landing during a dismissal left the latch desynced from any presentation —
the first tap(s) after a dismissal were swallowed. Fix: the sheet binds directly
to `model.recentsRequest` — every request carries a fresh monotonic id, so a
same-agent reopen is a real nil → request transition — and `.onDismiss` runs
`recentsSheetDismissed()`: a clean dismissal leaves the request nil; a request
that landed while the previous sheet was dismissing is re-armed with a fresh id
and presents on the completed dismissal. Discriminating model regressions cover
same-agent reopen cycles, clean-close clearing, and mid-dismissal re-arm; the
source-wiring tests pin the view call sites.
