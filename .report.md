## Verdict (from the numbers)

The regression is the **per-scroll-tick re-render of the whole herd**: the pager
offset lived in `@State var scroll` on `HerdView`, so every horizontal tick
re-ran `HerdView.body`, which at build 32 rebuilds #568's **eager** row stacks
(per realized row: `herdArtBounds`, the `HerdEdgeGroup` body, two content
passes). Build 31's rows are a `LazyVGrid` (visible cells only), ~4× cheaper.

Per scroll tick (drag legs t1/t2, A2 = build-32 pre-fix vs B = build-31):
`rowBuilds` 79.3/79.7 vs 22.8/21.7; `artBounds` 37.8/37.5 vs n/a;
`edgeGroupBodies` 37.5/37.5 vs n/a; `paddockProjections` 23.9/25.5 vs
20.3/21.1; `herdViewBody` 1.47/1.57 vs 1.21/1.24. The six `RanchEnvironment`
plane repaints (6/tick) and the deterministic fixture are identical in both
arms — shared cost, not the regression. A1 reproduced A2 within ~2 % on every
counter (the brief's A/B/A noise check passes).

## Fix (three measured changes, `ios/FleetNotifier/UI/Herd/HerdView.swift`)

1. Pager offset published through `HerdScrollChannel`, observed only by the new
   `HerdRanchLayer` (same `RanchEnvironment` inputs as before).
2. Pager pages enumerated (`ForEach(Array(paddocks.enumerated()), id:.element.id)`)
   so the per-page background stops re-deriving the projection per geometry update.
3. `HerdFieldRowStack` hoists the eager rows out of `HerdPaddockScroll`'s
   per-frame `GeometryReader` body (canonical viewport; unused `x` pinned), so a
   horizontal slide no longer rebuilds rows; vertical scrolling still updates
   rows through the measured row frames and #568's overlay still paints from the
   current layout pass.

After (F3 = fixed head, per tick t1/t2): `rowBuilds` **29.1/25.4**,
`artBounds` **6.7/4.9**, `edgeGroupBodies` **6.5/4.9**, `paddockProjections`
**3.6/3.0**, `herdViewBody` **0.36/0.30**. Per page turn: row builds
**701 → 339** (build-31 parity: 341). F (fix 1) and F2 (fixes 1+2) isolate each
step: rows 79→49→29 per tick, artBounds 38→24→7, projections 24→10→3.6.

Residual (documented in the evidence report): the ranch's 6 plane repaints per
tick (shared with build 31, untouched) and #568's own per-frame edge-opacity
evaluation (~20/tick), which cannot be removed without changing #568's
"paint from the current layout pass" semantics.
