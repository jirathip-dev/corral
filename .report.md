## Root cause (why Settings was invisible)

The #354 L2 cut deleted the board's `NavigationStack(path:)` wrapper
(`git show 75356cc` removes it from the FleetView body). #362/#364 later
re-attached `.navigationTitle("Fleet")` + `.toolbar` to the board `List`, but
WITHOUT a navigation shell those modifiers render nothing — the
`slider.horizontal.3` menu (the only Settings entry) never appeared on the
board at all. #365 restores the shell and makes the Settings control an
always-visible top-bar gear.

## Changed files (iOS only — fences respected: no egui/daemon/crates/docs edits)

- `ios/FleetNotifier/UI/FleetViews.swift`
  - `FleetView.body` wraps the board `List` in a `NavigationStack` again (the
    chrome chain — title/toolbar/sheets — sits inside it).
  - Toolbar: ALWAYS-VISIBLE plain `Button` with the system `gearshape`,
    `>=44pt` (`frame(minWidth: 44, minHeight: 44)`), VoiceOver

  - `SettingsView`: new leading `Connection` section — host `TextField`
    (pre-filled from the ACTIVE host, loopback default on a fresh board),
    `SecureField` registration token, and a register button that routes
    through the real `model.register(host:token:)` (same enable rules as the
    RegistrationView connect section). Removed the now-redundant read-only
    Host row from the Device section (single host surface). Notifications
    toggle + Reset retained unchanged.
  - DEBUG evidence driver `runSettingsSequence()` for
    `-corralDemoSettingsEvidence` (board → gear → Settings sheet open).
- `ios/FleetNotifier/App/AppModel.swift` — `register()` host-switch stream
  semantics (see AC3): when an already-paired device registers a DIFFERENT
  host, the current host's SSE stream is dropped (`stopLive()`) BEFORE the
  new pairing (`FleetStore.connect()` no-ops while a stream runs, so without
  this the board would keep streaming the old host forever); on a FAILED
  switch while live, the old host's stream is restarted behind the
  `register_failed` banner (both catch paths).
- `ios/FleetNotifier/App/FleetNotifierApp.swift` — Debug-only
  `-corralDemoSettingsEvidence` launch arg (evidence driver gate).
- `ios/FleetNotifierTests/FleetNotifierTests.swift` — new classes:
  `SettingsAccessWiringTests` (4 source-wiring pins over the bundled
  FleetViews.swift.txt) + `SettingsHostSwitchTests` (2 model regressions
  driving the real `register()`/`FleetStore` byte path through a URL-keyed,
  hold-open URLProtocol).
- `ios/check-release-demo.py` — digest re-pins (below).
