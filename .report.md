## Changed

- Added an optional `body` field to the egui issue wire model. The existing daemon `GET /issues` response already carries this body from the prior read-only issue wire work, so no new endpoint was needed.
- Reworked the Issues view around a scrollable left repository rail sourced from the existing grouped issue map. Empty categories remain visible, while the initial selection prefers the first category with issues.
- The selected repository now owns the visible issue list; the existing open/closed filter, title/number search, refresh, fleet identity resolution, and capability-gated `start_worktree` action remain in place.
- Expanded rows render an inline detail panel with state and labels, repository/number/state metadata, body text (including simple markdown headings and bullets), read-only notice, existing action gates, and collapse control.
- Added a body-bearing demo fixture entry and focused decoder, expansion, repository-switching, and fixture coverage.

## Design conformance

- V1: permanent left-side repository rail, repository counts, selected-state treatment, dark dashboard tokens, and a main selected-repository pane.
- V3: inline expanded detail panel with title retained in the row, state/label badges, metadata, readable body, read-only note, existing action treatment, and collapse affordance.
- Egui adaptation: body rendering uses a small stdlib-only markdown subset rather than adding a markdown dependency; the daemon wire does not provide an opened date, so metadata uses repository, issue number, and state instead.
