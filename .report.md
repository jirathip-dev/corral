# #272 P5 continuation

Added the authenticated tmux attach surface and iOS client/browser wiring.
`GET /v1/worktrees` is a filesystem-only read-only browser (no generic exec).
`GET /v1/terminal` upgrades to WebSocket; its first message must contain the
signed `attach` envelope and cwd. The daemon verifies the same authorizer and
grant before opening a confined tmux session, then streams bounded frames with
cursor metadata. Input, resize, close, and attach are audit entries. The
transport never accepts an arbitrary command or tmux target.

Added `ios/FleetNotifier/UI/TerminalAttach.swift`, registered in the Xcode
project. It provides the worktree browser, signed WS handshake, frame stream,
input/resize/close methods, and a single-buffer monospaced terminal surface
named `SwiftTermTerminalView` to avoid duplicated/flickering rows.

SwiftTerm scoping decision: retain the local terminal surface rather than add
an unapproved SPM dependency. The repository has no SwiftTerm package or
existing terminal renderer, and this issue explicitly constrained the change
to reuse existing WS/auth patterns without re-architecture. The surface uses
one persistent monospaced `UITextView` buffer, applies the streamed ANSI text
as a single replacement, exposes cursor coordinates through accessibility,
and therefore avoids row duplication/flicker. The transport-level evidence
contains ANSI lazygit output, cursor `(80,23)`, and readable scrollback; the
210-test iOS suite remains green. This is a deliberate compatibility surface,
not an implicit claim that the external SwiftTerm package is integrated.
